## Practice library

Practice resources are organised first by language and then by problem-solving pattern:

```text
Leetcode-Typescript/
└── Session-XX-Topic-Name/
    ├── README.md
    ├── Problems.md
    └── Solutions/
```

Each session README explains the topic, prerequisites and the recommended way to work through its problem set.

Open the [TypeScript practice folder](Leetcode-Typescript/) and choose a numbered session. Each session has its own README explaining the topic, prerequisites and recommended problem order.

The folder structure is the practice index, so this main README does not need a manually maintained list of sessions or problems.

## How to practise

1. Choose a topic from the practice library.
2. Read its topic guide and select the next recommended problem.
3. Write down the input, output and constraints in your own words.
4. Start with a correct solution before optimising it.
5. Test edge cases and record the time and space complexity.
6. Open the topic's `Solutions/` folder only after completing a serious attempt.
7. Compare the approaches, then revisit the problem without notes later.

## Fork the repository

Please [fork this repository](https://github.com/Unlock-Her-Tech/She-Leads-Tech-Practice/fork) before working through the practice exercises so you have your own copy on GitHub.

1. Select **Fork** at the top of the [Practice repository](https://github.com/Unlock-Her-Tech/She-Leads-Tech-Practice).
2. Choose your GitHub account and select **Create fork**.
3. Work in your fork to save your notes, solutions and changes.

You can use **Sync fork** on GitHub to keep your copy up to date. To propose improvements, open a pull request from your fork to the original repository.

## Contributing a solution

Contributions are welcome when they add a new approach or make an existing solution easier to understand.

1. Create a branch from the latest `main`, such as `practice-session-02-your-name`.
2. Put each solution in the matching session's `Solutions/` folder.
3. Use a descriptive filename and include complexity notes where helpful.
4. Test the solution against normal and edge cases.
5. Commit and push your branch:

```bash
git add .
git commit -m "Add Session 02 solution"
git push origin practice-session-02-your-name
```

6. Open a pull request from your fork to the original repository's `main` branch and explain your approach.

Please do not replace another contributor's valid approach merely because yours is different—multiple clear approaches can be useful for learning.
